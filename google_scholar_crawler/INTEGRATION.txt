Google Scholar citation synchronization

Profile: Xiang Zhang / mz4NUCAAAAAJ

The page continues to display Google Scholar citations, h-index, i10-index and the annual citation chart. SerpApi changes the transport, not the bibliometric source. Other indexes such as OpenAlex have different coverage and are not substituted into Scholar values.

Recommended setup for GitHub-hosted runners
1. Create a free SerpApi account at https://serpapi.com/users/sign_up and find your API key in the dashboard. Check the current free-plan allowance at https://serpapi.com/pricing. One daily author summary requires around 31 successful searches per month.
2. In this repository, open Settings > Secrets and variables > Actions > New repository secret. Name it SERPAPI_API_KEY and paste the key as the secret value. Do not put the key in source files, chat messages, workflow text, command-line arguments or repository variables.
3. Run Actions > Update Google Scholar metrics > Run workflow. The default transport mode is auto: it chooses SerpApi if the secret is set, otherwise it tries one ordinary public Scholar request. A repository variable GOOGLE_SCHOLAR_PROVIDER may explicitly select serpapi or direct.
4. Verify the run succeeded and google-scholar-stats/scholar_metrics.json contains the correct scholar_id, source=Google Scholar, retrieved_via=SerpApi and the observation timestamp returned by the provider. The homepage picks up a newer validated JSON without rebuilding the site.

Schedule and publication
- Daily at approximately 16:17 Asia/Shanghai; GitHub may delay scheduled runs.
- The existing GITHUB_TOKEN (contents:write) publishes only successful data using a normal push, shared concurrency with journal updates, and no force push.
- scholar_metrics.json contains metrics; citation_history.json retains one observed snapshot per date; gs_data_shieldsio.json preserves the legacy badge.
- Existing gs_data.json and per-paper records are retained.

Data and failure handling
- Total citations come from cited_by.table, not the sum of the first page of papers.
- Annual bars come from cited_by.graph, not publication-year counts.
- Author ID and Scholar profile URL must both match the requested profile.
- API cached responses retain their actual observation time. An older response never overwrites a newer snapshot or history.
- A missing/invalid key, quota error, HTTP 403/429, malformed data or identity mismatch fails the update and leaves existing files intact. Raw credential-bearing URLs and response bodies are not printed.
- Without a SerpApi secret, a GitHub-hosted direct request may still be refused by Scholar. The integration is not activated merely by deploying its code.

Local or offline import
- python google_scholar_crawler/update_metrics.py --html-file profile.html --output-dir results
- python google_scholar_crawler/update_metrics.py --json-file serpapi-result.json --output-dir results
These parse already obtained author summaries; they do not relabel another citation index as Google Scholar.
